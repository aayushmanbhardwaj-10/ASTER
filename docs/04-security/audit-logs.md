# Audit Logs
Audit logging in ASTER is comprehensive, immutable, and tamper‑evident. Every security‑relevant event—authentication attempts, authorization decisions, data reads/writes, configuration changes, secret accesses, and privileged operations—is recorded with a consistent schema that includes timestamp, actor identity, source IP, action performed, resource identifier, outcome, and relevant context (e.g., request payload hash). Logs are written append‑only to a write‑once, read‑many store (e.g., AWS S3 Object Lock, Azure Immutable Blob Storage) and forwarded in real time to a SIEM or log‑analytics platform for correlation, alerting, and retention per regulatory requirements (typically ≥7 years for financial records). Log integrity is protected via cryptographic chaining (hash‑linked entries) and periodic signing, enabling verification that logs have not been altered. Access to audit logs is strictly limited to authorized auditors and security personnel, with all access itself logged.
