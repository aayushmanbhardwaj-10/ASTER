# Secret Management
Secrets—API keys, database credentials, certificates, and encryption keys—are never hard‑coded or stored in plain text within repositories or container images. They are managed exclusively through a dedicated secrets vault (e.g., HashiCorp Vault, AWS Secrets Manager, Azure Key Vault) with dynamic, short‑lived credentials where possible. Access to secrets is governed by the same strict authentication and authorization policies that protect the application, and every secret retrieval is audited. Secrets are injected into runtime environments at the last possible moment (e.g., via sidecar containers or init containers) and are purged from memory as soon as they are no longer needed. Regular rotation, automated expiry, and breach‑detection mechanisms (e.g., honeytokens) further reduce the attack surface.
