# Authorization Philosophy
Authorization in ASTER follows the principle of least privilege, expressed through fine‑grained, attribute‑based access control (ABAC) roles tied to job functions, data sensitivity, and contextual attributes (e.g., location, device posture). Permissions are defined declaratively in policy‑as‑code (OPA/Rego) and version‑controlled alongside application code, enabling automated policy testing and drift detection. We enforce separation of duties by ensuring that no single role can both initiate and approve high‑risk financial actions (e.g., trade execution and settlement). Access decisions are made at the API gateway and enforced again at the service layer (defense‑in‑depth). All grant and revocation events are logged and trigger real‑time alerts for anomalous privilege escalation attempts.
